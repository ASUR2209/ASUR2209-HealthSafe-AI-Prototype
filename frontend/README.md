# HealthSafe AI — web frontend

React + Vite frontend for the Flask API in `../backend`.

## Run

```bash
# 1. backend (from repo root)
python backend/app.py            # serves http://localhost:5000

# 2. frontend
cd frontend
npm install
npm run dev                      # http://localhost:5173
```

The dev server proxies `/api/*` to `http://127.0.0.1:5000`. Point it elsewhere with
`HEALTHSAFE_API=http://host:port npm run dev`, or build against a deployed API with
`VITE_API_URL=https://api.example.com npm run build`.

A production build **without** `VITE_API_URL` (like the GitHub Pages one) needs no server:
`src/engine/` answers every API route in the browser with the same model and rules.

- `engine/model.ts` — TF-IDF + XGBoost inference from `public/engine/model.json`
- `engine/pipeline.ts` — `predict_safety_full` and the rule engine, ported from `backend/app.py`
- `engine/ocr.ts` — Tesseract via tesseract.js, plus `parse_ingredients`
- `engine/local.ts` — the routes: scan, OCR, barcode, alternatives, household (localStorage)

`model.json`, `rules.json` and `products.json` are generated by `ml/export_browser_model.py`.

In dev, if Flask is down, typed scans fall back to a small demo rule set (marked "demo
engine" in the readout). Photo scans through Flask need Tesseract at
`C:\Program Files\Tesseract-OCR`.

## Layout

- `src/Lightbox.tsx` — the readout: one well per ingredient, one lane per pipeline layer
  (personal rules, ingredient heuristic, XGBoost).
- `src/Composer.tsx` — typed text, label photo (`/ocr/analyze`), barcode (`/scan-barcode`).
- `src/ProfilePanel.tsx` — conditions and medicines sent as `user_profile`.
- `src/Findings.tsx` — flags, medicine conflicts, alternatives (`/recommend`).
- `src/Household.tsx` — `/family/*` register, login, dashboard, members.
- `src/api.ts` — API client and response normalisation.
